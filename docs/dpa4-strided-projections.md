# DPA4 CPU / CUDA 数据布局优化

日期：2026-09-07。

## 算法与优化依据

当前原生实现针对内置模型：64 通道、lmax=3、3 个交互块。

1. 截断邻居图确定边；距离基函数、类型嵌入和环境网络生成初始节点及径向特征。
2. 每个交互块将节点的 16 个球谐分量旋转到边坐标系，保留 10 个分量：m=0 的 4 个分量，以及 m=±1 各 3 个分量。
3. 径向混合器把 256 维径向特征投影为 25 个系数（4×4 + 3×3），两个有符号分支共享后者。随后执行 4 层 SO(2) 线性变换，前三层带门控与残差。
4. 消息旋回全局坐标，经过注意力聚合、SO(3) 网格乘积与 FFN；最终输出每个原子的 64 维标量描述符。网格分支使用 3 个 frame、48 个系数和 152 个网格点。

设边数为 E、节点数为 N、通道数为 C。固定角动量阶数时，SO(2) 稠密投影计算量随 E·C² 增长，节点投影随 N·C² 增长；边中间张量存储随 E·C 增长。以下优化保持网络、邻居截断和计算精度，主要减少投影前的数据搬运、分配和重复非线性计算，没有改变复杂度阶数。

## CPU

- 原始边布局为 `[E, 640]`。m=0 直接以行跨度 640 输入 BLAS，省掉 `[E, 256]` 打包。
- m=±1 从每条边的偏移 256 / 448 直接读取，各执行一次 `[E, 192] × [192, 384]`。直接使用 checkpoint 中并排存储的实部/虚部权重，省掉输入打包和权重拆分。仍按 `negative_u - positive_v`、`negative_v + positive_u` 合成输出。
- 门控直接读取边张量；每个 degree/channel 的 sigmoid 计算一次，由三个对应分量复用。
- 径向混合和注意力偏置直接读取原始 `[E, 256]` 特征，删除每块 `[E, 640]` 的扩展缓冲区，少分配 2560E 字节。
- 删除批量网格工作区中两个从未被使用的系数缓冲区。

## CUDA

- m=0 使用行跨度 640 直接投影。
- m=±1 使用两个共享权重的 GEMM batch：输入 batch 跨度为 192，输入行跨度为 640，输出 batch 跨度为 384E。这保留了后续 kernel 需要的两个连续输出区。
- 每层省掉两个打包 kernel，3 个交互块共省掉 24 次启动；删除 `[2E, 192]` 的打包工作区，少分配 1536E 字节。`radial_input` 仍供环境/径向网络使用，予以保留。

## 第二轮：网格并行（2026-09-08）

本轮以第一轮完成后的源码重新编译为基线，前后均使用相同 Release 配置。不要把不同日期测量的绝对耗时直接相除。

CPU 的消息、FFN 和输出网格原先依次处理 64 节点的 tile，每次 BLAS 调用只使用一个线程。现在由最多 `min(num_threads, ceil(N / 64))` 个工作线程同时处理独立 tile，BLAS 仍保持单线程；多 tile 并行时关闭 tile 内的多线程，避免嵌套争抢。每个 worker 的工作区跨交互块复用，输出写入互不重叠的节点区间，tile 的矩阵形状和点积顺序保持不变。代价是 CPU 网格临时空间随实际 worker 数增长，而非仅保留一份。

CUDA 消息分支的 frame 展开、网格投影、网格乘积和反投影改用现有的 GEMM/逐元素内核；末端门控、frame 收缩及标量残差仍按原有顺序累加。64 通道消息所需空间只有最大 384 通道网格分支的六分之一，因此消息 tile 可从 128 扩大到 768 节点，复用原先的三个 scratch 缓冲区，不增加 CUDA 工作区容量。其他网格分支仍使用 128 节点 tile。

独立 CUDA event 实验中，512 节点消息计算由四个 128 节点旧 kernel 合计约 2.55 ms，降至单批 GEMM 路径约 1.22 ms；这是合成输入下的局部测量，端到端结果如下。未采用半精度、fast-math 或新的容差。

| CPU / 4 线程 | 2048 | 12.89585 s | 11.36137 s | 11.90% |

### 混合孤立原子精度修复（2026-09-08）

该问题已修复。最小复现为同一非周期结构中的一对 H2（间距 0.9 Å）加一个远处 H（坐标 10 Å）：修复前孤立原子的 64 个输出分量错误，最大绝对差约 4.96。384 对 H2 加孤立 H 的原始 769 原子案例也复现同一问题。

根因有两处：CUDA 按逐原子邻居标记恢复状态，而 CPU/NumPy 参考只跳过整帧无真实边的交互块；并且原恢复路径把 `message` 同时用作状态快照和消息输出，恢复时快照已经被覆盖。前者误处理连通帧中的孤立原子，后者也损坏了纯孤立帧的输出。

现在 GPU 在几何准备后，将真实边活跃标记按帧归并并广播（不把精确 self-edge 当作真实边）。交互块写回结果时，只有活跃帧写入 `state0`；纯孤立帧保留原状态。删除快照复制和恢复 kernel，以及初始化阶段未使用的活跃标记参数。新增一次帧标记 kernel，删除三个交互块共六次复制/恢复启动；无需新增大型缓冲区或主机同步，保持前述网格优化。

修复后的 20 项 CPU/CUDA 测试通过。新增四种回归组合覆盖 3/769 原子的混合结构，以及前后夹有纯孤立帧的批次；最小案例同时对照独立 NumPy 参考，且验证逐帧计算及不同批次重复使用同一 CUDA 实例。保持原有 CPU/CUDA 容差 `atol=1e-5, rtol=2e-5`。

普通连通碳结构的 512/2048 原子输出与修复前逐位一致。各预热一次、计时三次，中位耗时分别由 0.17058/0.59642 s 变为 0.16197/0.56454 s，未观察到性能回退；样本少且存在运行负载波动，不据此主张额外稳定加速比例。原始数组和计时位于 `/tmp/dpa4-isolated-perf-{before,after}.{npz,json}`。

## BLAS 占比与初始化批量化（2026-09-08）

本轮直接测量了 `scipy_cblas_sgemm`，并使用已有 `MDESCRIPTOR_DPA4_PROFILE` 阶段计时。512 原子、26080 条边、1 线程，预热加一次计时共两次计算：总阶段耗时 11.74321 s，4192 次 SGEMM 合计 3.87774 s，占约 **33.0%**。用单线程测量，避免把多个 OpenMP worker 的重叠时间当作串行占比。该比例只代表本次样本与构建。

当前 CPU 链接 OpenBLAS 0.3.34.106.0，运行时报告 `DYNAMIC_ARCH` / `SkylakeX` 内核。BLAS 内部设置为 1 线程，外层 OpenMP 按 `ExecutionOptions.num_threads` 并行；这不意味着整个 DPA4 只使用一个核心。CUDA 路径使用自定义 GEMM kernel，并没有调用 cuBLAS；本次优化只修改 CPU。

主要 BLAS 调用已经是 `1024×192 · 192×384`、`1024×256 · 256×256` 等批量矩阵乘法。与此同时，环境与径向初始化仍按每条边调用手写 matvec，初始化约占单线程总时间的 22%。因此本轮将以下六层共享权重投影按 1024 条边分块交给 SGEMM：

- 环境网络：16→32→32，以及拼接两端各 16 维类型嵌入后的 64→128→64。
- 径向网络：16→64，保留逐边 RMSNorm / SiLU 后，再做 64→256。

原有节点聚合顺序、FP32 数据类型、非线性公式与 FP64 的环境输出投影保持不变。环境中间特征额外使用 `E×64` 个 float，即 256E 字节（26080 条边约 6.37 MiB），在环境阶段结束时释放；每个活动环境 tile 的三个矩阵共约 896 KiB。未增加 BLAS 内部线程，未启用 fast-math 或半精度。

同样的单线程阶段测量中，初始化从约 1.312 s 降至 0.062 s；两次计算的 SGEMM 合计仍约 3.88 s，总时间降至约 9.09 s。BLAS 时间占比提高到约 43%，主要来自其他耗时的下降。对应 512 原子的新旧输出逐位一致。

4 线程端到端基准（每个规模预热一次、计时三次，中位数；前后相同 Release / 阶段计时构建，不加载 BLAS 拦截器）：

| 原子数 | 本轮基线 | 批量初始化后 | 耗时降低 |
| --- | ---: | ---: | ---: |
| 512 | 2.72660 s | 2.34477 s | 14.00% |
| 2048 | 12.34371 s | 10.58614 s | 14.24% |

512/2048 原子的端到端新旧输出均逐位一致。新增 NumPy 参考回归使用 33 个互为邻居的原子形成 1056 条有向边，跨越 1024 条边的分块边界，覆盖两种元素及另一个孤立原子。精度容差保持 `rtol=2e-5, atol=4e-5`，没有为此次改动放宽阈值。

最终 CPU 的 `tests/test_dpa4.py` 与 `tests/test_dpa4_golden.py` 共 12 项通过，Release 构建、Ruff 和 `git diff --check` 通过。

## CUDA 自定义 GEMM 优化（2026-09-08）

本轮以此前所有修复和优化后的 CUDA 源码为基线，在 RTX 2080 SUPER 上使用 CUDA 13.3 / SM75 / Release 构建。保留 FP32 逐项 `fmaf` 的 K 维累加顺序，不使用半精度、Tensor Core 或 fast-math。

两个原有的大矩阵 kernel 合并为一个模板内核，提供 64/128 两种列 tile：

- 128 个线程组成一个 block，半个 warp 对应 16 个相邻输出列。
- 每线程计算 8 行、4 或 8 列，显式复用读入寄存器的 A/B 值。
- A 的共享内存 tile 从 `[64][16]` 改为 `[64][17]`，分开同一 warp 中两个行组的共享内存 bank；列访问与写回按相邻线程连续分布。
- 对 `N>=384, K>=128, M>=64` 的较宽、较深投影选择 128 列，其余大矩阵选择 64 列。小矩阵与 64 位索引路径保留原实现，超大 grid 的拆分逻辑保持不变。

候选内核用代表性矩阵形状进行 CUDA event 计时，并与旧内核逐位比较。选中配置的部分局部结果如下（不等同于完整 DPA4 的加速比例）：

| 6144 / 384 / 384 / 1 | 0.40197 ms | 0.24381 ms |

同步公共 `compute` 调用的端到端基准，每个规模预热一次、计时九次取中位数：

两个规模的新旧输出均逐位一致。测试 `tests/gpu/dpa4_gemm_launch.cu` 新增 21 个直接 GEMM 案例，使用按 K 顺序累加的 CPU FP32 FMA 作为精确参考：覆盖 M/N/K 尾部、两种大矩阵调度分支、共享 A/B、非零 batch stride、径向交错布局，以及输出 padding 不被覆盖。原有 rows=1048561 / batches=65536 的两个 launch 边界测试也通过。

## CPU 缓存分块与边网络融合（2026-09-09）

64 原子帧原来只有一个 64 节点网格 tile，SO(3) 投影同样只有一个
node tile；增加 OpenMP 线程无法并行这些单线程 BLAS 调用。边网络每层
另行按 1024 条边分块，并在每个线性层、门控和残差之间生成或遍历完整
边张量。4314 条边只能产生 5 个 BLAS 任务，且每层都需要同步。

本轮改动：

- 网格与 SO(3) 投影使用固定 4 节点 tile，使普通 32/64 原子帧也有足够
  的独立任务，并减小每个 worker 的网格工作集。网格 tile 内只用一个
  线程；划分不随线程数变化。
- 径向混合和四层 SO(2) 网络在同一个 128 边 tile 内连续完成，复用
  tile 内的中间数组。去掉这些内部函数原有的分块和 OpenMP 并行区，
  只在整条边网络外并行；径向输入直接读取原数组。
- 旋转和标量门控按连续通道遍历，允许向量化独立输出，保持每个输出
  原有的 FP64 累加顺序。未引入 fast-math 或降低精度。

测试机为 Ryzen 9 7950X（16 核 / 32 逻辑 CPU，WSL），GCC 13.3.0，
Release 构建，关闭阶段计时，OpenBLAS 0.3.34.106.0 内部保持单线程。
基线为本轮开始时已安装并保存的 CPU 扩展。每组预热一次、计时三次，
下表为端到端 `compute` 中位数，不含模型构造与数据文件读取。

| 工作负载 | 线程 | 优化前 | 优化后 | 加速 |
| --- | ---: | ---: | ---: | ---: |
| carbon_dataset_pbc 前 4 帧，共 256 原子 | 1 | 2.00847 s | 1.62082 s | 1.24× |
| 同上 | 16 | 1.37173 s | 0.35578 s | 3.86× |
| 同上 | 32 | 2.25648 s | 0.64554 s | 3.50× |
| train.xyz 第 4096 帧，512 原子 | 16 | 1.83054 s | 0.69786 s | 2.62× |
| train.xyz 第 4096–4099 帧，共 2048 原子 | 16 | 8.25349 s | 3.00896 s | 2.74× |

256 原子批次的 16 线程相对单线程加速比由 1.46× 提升为 4.56×。
32 线程仍慢于 16 线程，因此本机这些工作负载以 16 线程更合适；不能把
逻辑线程翻倍理解为计算资源翻倍。额外的 64 原子诊断实验中，设置
`OMP_WAIT_POLICY=PASSIVE` 将 32 线程约 0.167 s 降至 0.115 s，说明
等待策略也有影响；这只是单独的运行时实验，生产实现和上表均未设置它。

并行度提高也有内存代价。256 原子稳态进程峰值 RSS（包含 Python、模型等）
在 1/16/32 线程下分别由 293080/316340/313832 KiB 变为

验证：40 项 DPA4、DPA4C、控制/取消及 golden 测试通过。网格回归覆盖
1/2/4/16/32 线程、worker 重复处理 tile 和尾块；NumPy 参考回归覆盖

SO(3) GEMM 形状改变允许出现浮点舍入差，未放宽测试阈值。
初次沙箱执行无法访问 GPU；随后在宿主机执行，成功访问 RTX 2080 SUPER
（驱动 610.47），9 项 DPA4 CUDA 对照测试全部通过。

## CPU 旋转与完整 FFN 分块融合（2026-09-10）

本轮接续上一轮优化。分阶段计时发现，512 原子、26080 条边、16 线程时，
每个交互块的输入旋转阶段约 40 ms、输出旋转阶段约 48 ms；这些阶段包含
完整边张量的分配、清零和遍历。FFN 与输出头还在节点分块外生成整帧的
1152/576 通道隐藏张量。

进一步改动：

- 两端旋转、径向混合、四层 SO(2) 网络在同一个 128 边 tile 内完成。
  每个线程跨 tile 复用旋转、线性与门控工作区，删除全量局部边张量。
  最终消息数组不再预先串行清零；每个 tile 写满自己的互不重叠区间，
  并行区结束后注意力才读取它。尾块与稠密结构由参考回归覆盖。
- FFN 的前后 SO(3) 投影移入 4 节点 tile，完整 FFN 现在由
  `block_ffn_batch` 处理。输出头也在 tile 内完成，避免整帧隐藏张量。
- Q/K 归一化后以两个 SGEMM 批量投影，删除逐节点串行 matvec。
  注意力的逐边累加顺序保持不变。
- `output_head_batch` 最后只投影公开描述符使用的 l=0 行，直接按节点
  步长读取 576 通道，省去未使用的 l=1/2/3 输出与整帧输出中间数组。

正式构建使用 Release，`MDESCRIPTOR_DPA4_PROFILE=OFF`，BLAS 内部一个线程。
本轮 CPU/CUDA 基准在宿主机顺序执行，各预热一次、计时三次，记录同步
`compute` 中位数。前值来自上一轮保存的原始采样，并非本轮同时重跑的
旧构建，因此仍有跨次运行波动。

## 第三轮：按需回投影与边消息即时聚合（2026-09-10）

本轮保留了第二轮的 CPU 二进制和源码快照，在宿主机对同一组输入顺序
运行旧、新构建，各预热一次、计时五次。两者均为 Release、profiling OFF，
OpenBLAS 内部使用一个线程；没有调整线程绑定、等待策略或精度设置。

最终实现：

- 输出头只回投影 l=0 对应的三个 frame 系数，随后也只对这三行进行
  通道投影和门控。前向网格仍使用全部 48 个输入系数，未删除其贡献。
- Wigner 旋转按阶执行，跳过不同阶之间恒为零的乘积。相同阶的有效
  乘加顺序保持不变，输出方向按连续通道计算。
- 四元数四次项和 monomial 基函数按每条边计算一次，再供各矩阵元素
  使用，避免同一项重复计算 25/49 次；不改变各元素的求和顺序。
- 先计算注意力权重，再以完整目标原子分组生成和立即累加边消息。
  小于 128 原子的帧每组一个原子，其余每组四个原子；组内最多一次
  处理 128 条边。每个目标只由一个线程负责，跨边块继续原有 FP64
  累加，不使用原子操作，也不再保留完整的 `E×16×64` 消息数组。
  分组不依赖线程数。按邻居数量动态分组的候选存在小矩阵开销，已撤掉。

16 线程最终端到端中位数：

| 原子数 | 第二轮保留构建 | 第三轮 | 加速 |
| --- | ---: | ---: | ---: |
| 512 | 0.35505 s | 0.32975 s | 1.08× |
| 2048（4 帧） | 1.74617 s | 1.46578 s | 1.19× |

初始设定的 512 原子低于 300 ms 的实验目标没有稳定达到；上表给出实际
收益，不以某一次较快采样代替中位数。3/32/64 原子结构分别扫描
1/16/32 线程，本次采样未观察到回退，但部分小幅变化仍属于运行波动。
例如 C64 单线程由 0.40537 s 降至 0.38409 s，16 线程为
0.06366→0.06309 s，基本持平；HEA32 的 16 线程为 0.05014→0.04351 s。

同一进程工作负载（先 512、再 2048 原子）的峰值 RSS，由 478144 KiB
降到 347024 KiB，下降 **27.4%**。RSS 包含 Python、模型和输入输出等，
不是纯内核空间。消除的完整边消息在 26080 条边时约占 101.9 MiB。

最终构建的 **52 项测试通过**（43 项 CPU、9 项 CUDA）。新增一个含
178 个周期镜像邻居的单原子案例，验证同一目标跨多个边块时的注意力
累加，并对照 NumPy 参考及 1/4/16 线程结果。全部新旧 CPU 基准输出
逐元素一致；另外以随机四元数和系数做了 3000 组 Wigner 新旧实现对照，
覆盖 tensor l=2 与 monomial l=2/l=3，输出逐位一致。

本轮宿主机 CUDA 中位耗时分别为 0.12703/0.45309 s，CPU/CUDA 耗时比
约为 2.60×/3.24×。最终 CPU/CUDA 输出按既有 `rtol=2e-5, atol=1e-5`
检查通过，未放宽阈值。CUDA 实现未修改。

`benchmarks/dpa-comparison/20260910/round3/summary.json` 及同目录文件。
